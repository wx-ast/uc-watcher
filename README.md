# UC Watchdog

Нативный фоновый агент на Swift для восстановления Universal Control между Mac.
Он отслеживает живой системный журнал принимающего компьютера и при событии
`Device Unavailable` перезапускает пользовательские `sharingd` и Universal Control.
Программа работает без sudo и отключения SIP.
После подтверждённого восстановления отправляет стандартное уведомление macOS на принимающем Mac.

Проект использует Swift Package Manager. Монитор и установщик находятся
в `Sources/UCWatchdog/main.swift`, уведомления UserNotifications — в `RecoveryNotice.swift`;
настройки сборки — в `Package.swift`.
Для сборки нужны Xcode или Command Line Tools с Swift 5.9 или новее, для запуска —
macOS 13 или новее. Поставляемая ранее сборка и установленный агент проверены
на Apple Silicon; сборку для другой архитектуры следует проверить отдельно.

## Сборка и проверки

Из каталога проекта:

```sh
swift build -c release
.build/release/uc-watchdog self-test
.build/release/uc-watchdog check-processes
```

`self-test` проверяет восемнадцать сценариев и не отправляет сигналы службам.
`check-processes` показывает, какие процессы будут выбраны, также без сигналов.
Проверка чтения реальных событий без установки и восстановления:

```sh
.build/release/uc-watchdog monitor --peer 3047DD83 --dry-run --duration 30
```

## Установка

При первом открытии неустановленной копии `.app` приложение предлагает установку
для текущего пользователя. **Установить** копирует приложение, включает автозапуск
и запускает монитор. **Отмена** закрывает копию без установки и запуска монитора.
Если приложение уже установлено, внешняя копия предлагает **Открыть установленное**,
**Обновить** или **Отмена**. Установленная копия открывается сразу, без повторного вопроса.

Запускать установку на принимающем Mac под его обычным пользователем:

```sh
.build/release/uc-watchdog install --peer 3047DD83
```

Приложение запускается сразу и при каждом входе в систему через `SMAppService.mainApp`.
В строке меню появляется значок монитора. Старый LaunchAgent при обновлении удаляется. Для наблюдения без
перезапуска служб добавить `--dry-run` к команде установки.
`3047DD83` — IDS-префикс исходного Mac в текущей паре; в другой паре указать
ID из журнала Universal Control принимающего компьютера.

Для обновления установленного агента на `mbl`:

```sh
.build/release/uc-watchdog bundle --output /tmp/UCWatchdog-update.app
scp -r /tmp/UCWatchdog-update.app mbl:/tmp/
ssh mbl '"/tmp/UCWatchdog-update.app/Contents/MacOS/uc-watchdog" self-test'
ssh mbl '"/tmp/UCWatchdog-update.app/Contents/MacOS/uc-watchdog" install --peer 3047DD83'
ssh mbl rm -rf /tmp/UCWatchdog-update.app
```

Переносимый бинарник должен соответствовать архитектуре принимающего Mac.
Для переноса создайте `.app` командой `bundle`: он включает иконку и все
необходимые ресурсы. SwiftPM-бинарник использует соседний bundle ресурсов,
поэтому для установки на другом Mac переносите всё приложение.
Установщик сохраняет журнал, историю ограничений и выключенный автозапуск при обновлении.
На `mbl` уже установлен Swift-агент в режиме автоматического восстановления.
Обновление файлов этого проекта само по себе не обновляет установленный агент.

## Работа и ограничения

- Один `Device Lost` только записывается в журнал: обнаружение часто возвращается
  до отключения ввода. Восстановление начинается при `Device Unavailable`.
- На одно исчезновение приходится одна попытка, не чаще раза в две минуты
  и максимум три раза за десять минут. История сохраняется между запусками.
- Выбираются только процессы текущего пользователя с точными путями исполняемых
  файлов. Процессы симуляторов и других пользователей исключаются.
- `sharingd` получает SIGTERM, Universal Control — SIGKILL; их заново запускает
  macOS. Прямой `launchctl kickstart` системных служб блокируется SIP.
- Файловая блокировка исключает одновременную работу двух экземпляров.
- Перезапуск временно отключает удалённый ввод и может прервать AirDrop/Handoff.

Это обходной способ, а не исправление первопричины потери Bluetooth-обнаружения.
Ускорение восстановления при естественном обрыве ещё нужно проверить.
На отдельных версиях macOS чтение системного журнала может требовать дополнительных
прав; ошибки чтения фиксируются, но программа не может реагировать на отсутствующие события.

## Меню приложения

Нажмите значок монитора в строке меню macOS:

Заголовок меню — **Universal Control Watcher**. Под ним состояние: **Активен**,
**Остановлен**, **Только наблюдение** или **Перезапускается…**.

- **Запускать при входе** — включить или выключить автозапуск. Текущий монитор
  продолжает работать. При необходимости разрешите запуск в системных настройках.
- **Остановить** — остановить монитор и закрыть приложение вместе с меню.
  Автозапуск сохраняется: приложение вернётся при следующем входе в систему.
- **Открыть журнал** — открыть `watchdog.log` в приложении по умолчанию.
- **Показать приложение в Finder** — найти установленное приложение.
- **Настройки объектов входа…** — открыть системное управление автозапуском.
- **О программе…** — стандартное окно macOS с иконкой, версией, автором **wx-ast**
  и ссылкой на [исходный код приложения](https://github.com/wx-ast/uc-watcher).
- **Удалить приложение…** — после подтверждения остановить монитор, отключить
  автозапуск и удалить приложение. История и диагностические файлы сохраняются.

Чтобы снова открыть меню после завершения, откройте `UC Watchdog.app` в Finder
или выполните:

```sh
open "$HOME/Library/Application Support/UCWatchdog/UC Watchdog.app"
```

Меню запускает отдельный процесс мониторинга. Если тот неожиданно завершается,
меню повторяет запуск через 30 секунд. Если меню закрыто или аварийно завершилось,
монитор также останавливается. Два экземпляра меню или монитора одновременно
не работают. Для автозапуска используется системный объект входа; старый файл
`~/Library/LaunchAgents/local.uc-watchdog.plist` больше не создаётся.

Проверка меню без изменения автозапуска, уведомлений и восстановления:

```sh
"/tmp/UC Watchdog.app/Contents/MacOS/uc-watchdog" menu-self-test
```

## Состояние, журналы и удаление


После реального обрыва уведомление «Связь восстановлена» отправляется только при
событии `Connected`, а не при одном `Device Available`. Оно показывает время
обрыва и восстановления, длительность и факт попытки watchdog. Если связь
вернулась без перезапуска служб из-за ограничения частоты, уведомление сообщает
об этом. Каждый обрыв получает отдельное уведомление в группе восстановления.

При первом запуске установленного приложения macOS запрашивает разрешение на
уведомления. Разрешите их для **UC Watchdog**. Стиль баннеров, показ на экране
блокировки и поведение в режиме фокусирования задаются в **Системные настройки →
Уведомления → UC Watchdog**. Постоянного окна и кнопки «Понятно» больше нет;
прочтением и удалением уведомлений управляет Центр уведомлений macOS.
Запрет уведомлений не мешает восстановлению; причина пропуска записывается в журнал.
`--dry-run` не запрашивает разрешение и не отправляет уведомления.

Проверить уведомление без отключения соединения на установленном агенте:

```sh
"$HOME/Library/Application Support/UCWatchdog/UC Watchdog.app/Contents/MacOS/uc-watchdog" preview-notification --duration 10
```

Для проверки до установки создайте отдельный bundle:

```sh
.build/release/uc-watchdog bundle --output "/tmp/UC Watchdog.app"
"/tmp/UC Watchdog.app/Contents/MacOS/uc-watchdog" preview-notification --duration 10
```

Каталог назначения команды `bundle` должен отсутствовать. Тестовое уведомление
имеет заголовок «Проверка уведомления» и не меняет историю восстановления.
`--duration` задаёт время работы тестового процесса после выдачи разрешения;
срок показа уведомления определяет macOS. Команда из голого SwiftPM-бинарника
не поддерживает уведомления, поэтому для их проверки нужен `.app`.

На компьютере, где установлен агент:

```sh
"$HOME/Library/Application Support/UCWatchdog/UC Watchdog.app/Contents/MacOS/uc-watchdog" status
tail -f "$HOME/Library/Logs/UCWatchdog/watchdog.log"
"$HOME/Library/Application Support/UCWatchdog/UC Watchdog.app/Contents/MacOS/uc-watchdog" uninstall
```

Установленные файлы:

- `~/Library/Application Support/UCWatchdog/UC Watchdog.app` — приложение с bundle ID
  `local.uc-watchdog`, локальной подписью, иконкой `Contents/Resources/AppIcon.icns`
  и исполняемым файлом `Contents/MacOS/uc-watchdog`.
- `~/Library/Logs/UCWatchdog/watchdog.log` — журнал с ротацией, до четырёх файлов
  примерно по 1 МБ; время записывается в часовом поясе компьютера.
- `~/Library/Logs/UCWatchdog/recovery-history.json` — история попыток.
- `~/Library/Logs/UCWatchdog/last-notification.json` — сохранённый файл старого окна,
  если оно использовалось ранее; новая версия его не изменяет.
- `~/Library/Logs/UCWatchdog/configuration.json` — IDS-префикс и режим наблюдения.
- `~/Library/Logs/UCWatchdog/menu.lock` — блокировка экземпляра меню.
- `~/Library/Logs/UCWatchdog/watchdog.lock` — блокировка экземпляра монитора.
- `~/Library/Logs/UCWatchdog/launcher.log` — сохранённый журнал запуска старого LaunchAgent.

Удаление останавливает агент, отключает системный объект входа и удаляет приложение.
Файлы старого LaunchAgent также удаляются, если остались от предыдущей версии. Диагностические
журналы и история остаются. Настройки Bluetooth, VPN и SIP программа не меняет.
